# meeting-note-regeneration Specification

## Purpose

Regenerate one meeting note from an already-transcribed file by re-running
only the analyzer, without touching topics, the index, or dedup state. New
capability — no existing spec.

## Requirements

### Requirement: `regenerate` command argument parsing

The system MUST accept `patro regenerate <transcript-file> [--date YYYY-MM-DD] [--mock] [--config PATH]` as a sibling of `serve`/`process`/`reconcile`/`run`. The transcript-file positional MUST be required; unknown flags MUST be rejected; `--date` MUST be command-scoped like the existing `--all`/`--dry-run` guard.

#### Scenario: Missing file, unknown flag, misplaced `--date`
- GIVEN `patro regenerate` (no positional), `patro regenerate notes.txt --bogus`, and `patro process file.mkv --date 2026-01-01`
- WHEN each is parsed
- THEN all three exit non-zero before any pipeline work, with no file I/O

#### Scenario: Valid combination parses
- GIVEN `patro regenerate notes.txt --date 2026-01-01 --mock`
- WHEN parsed
- THEN it succeeds and both flags apply together

### Requirement: Transcript source resolution

The system MUST derive the transcript ID from the filename stem when the input already lives under `knowledge/transcripts/`. Otherwise it MUST generate a new ID and copy the file unconditionally to `knowledge/transcripts/<id>.txt` — no prompt.

#### Scenario: In-library transcript reused
- GIVEN `knowledge/transcripts/abc123.txt` exists
- WHEN regenerated by that path
- THEN the ID is `abc123` and no copy occurs

#### Scenario: External transcript copied unconditionally
- GIVEN a file outside `knowledge/transcripts/`
- WHEN regenerated
- THEN a new ID is generated, the file is copied in with no prompt, and the note's transcript link resolves

### Requirement: Analyzer invocation without topic context

The system MUST invoke the analyzer selected by `cfg.AnalyzerBackend` (kimi/claude/codex/lemur) exactly as the existing pipeline does, passing `existing []types.TopicRef` as `nil` — structurally, not incidentally. It MUST NOT call `ExistingTopics`/`ExistingTopicsRecent` or read anything under `knowledge/topics/` or `knowledge/index.md`.

#### Scenario: Real backend called with nil topic context
- GIVEN `analyzer_backend: claude`, no `--mock`
- WHEN `regenerate` runs
- THEN the CLI is invoked as `process` invokes it, `existing` is `nil`, and no topic file is read

### Requirement: Meeting note write target resolution

The system MUST look up an existing note for the resolved transcript ID (scanning `knowledge/meetings/*.md` for its `../transcripts/<id>.txt` link). If found, it MUST overwrite that exact path, reusing its `- **Date:**`. If not found, it MUST compute `date + "-" + Slugify(title)` using `--date`, which becomes required; missing `--date` with no prior note MUST fail with a clear error rather than default to today.

#### Scenario: Prior note found — overwrite in place, date reused
- GIVEN a note at `.../2026-01-05-old-title.md` linked to transcript `abc123`
- WHEN `regenerate` produces title "New Title"
- THEN that same file is overwritten, `2026-01-05` is preserved, and no second file is created

#### Scenario: No prior note — `--date` required
- GIVEN no note links to transcript `xyz789`
- WHEN run with `--date 2026-02-01`, a new note is written at `.../2026-02-01-<slug>.md`
- BUT WHEN run without `--date`, it exits non-zero and writes no file

### Requirement: Topic, index, and state isolation

The system MUST NOT call `AddMeetingCtx`, `AppendTopicSectionAnnotated`, or `RebuildIndex`, and MUST NOT read or write anything under `knowledge/topics/` or `knowledge/index.md`. It MUST NOT call `IsProcessed`/`MarkProcessed`; `.state/processed.json` stays untouched. The status `Tracker` MUST be `nil`, matching `process`.

#### Scenario: Topics, index, and state byte-identical after a run
- GIVEN a library with existing topic files and `index.md`
- WHEN `patro regenerate <file> --mock` runs
- THEN `knowledge/topics/*.md`, `index.md`, and `.state/processed.json` are byte-identical before/after

### Requirement: Mock mode

`--mock` MUST produce a deterministic fake analysis (`pipeline.MockAnalyze` semantics) with no real subprocess or API call, matching `process --mock`.

#### Scenario: Mock run needs no network or CLI
- GIVEN no `ASSEMBLYAI_API_KEY` and no analyzer CLI installed
- WHEN `regenerate ... --mock` runs
- THEN it succeeds via `MockAnalyze`'s fixed output, zero external calls

### Requirement: Accepted metadata degradation for bare transcripts

Regenerating from a bare transcript (no `Chapters`/`Language`, produced only by AssemblyAI transcription) MUST still succeed, writing an empty `- **Language:**` value and omitting `## Chapters`. This is accepted, documented behavior, not a defect.

#### Scenario: Bare transcript yields empty language, no chapters
- GIVEN a plain `.txt` transcript with no chapter/language metadata
- WHEN the note is written
- THEN it has an empty `- **Language:**` line, no `## Chapters` section, and the write succeeds
